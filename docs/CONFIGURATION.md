# Configuration

Everything the suite touches, and how to change it.

## Server settings under test

The variant tables (`benchmarks/<domain>/variants.json`, generated by
`generate.py`) set these on the serving deployment per trial:

| Setting | Values | What it controls |
|---|---|---|
| `MLSERVER_REST_BINARY_TENSOR` | true/false | KServe v2 binary tensor REST framing (opt-in) |
| `MLSERVER_REST_WORKER_BINARY` | true/false | Binary parse/encode in workers (requires the above) |
| `MLSERVER_REST_WORKER_JSON` | true/false | JSON parse/encode in workers |
| `MLSERVER_GRPC_RAW_INPUT_BUFFERS` | true/false | Zero-copy gRPC input path |
| `MLSERVER_PARALLEL_WORKERS` | 1–12 | Inference worker processes |
| `MLSERVER_PARALLEL_INFERENCE_TRANSPORT` | queue/zmq | Frontend↔worker IPC |
| `MLSERVER_MODEL_ONNX_SESSION_OPTIONS` | JSON | `intra_op_num_threads`, `inter_op_num_threads` |
| `MLSERVER_MODEL_ONNX_SESSION_CONFIG_ENTRIES` | JSON | `session.intra_op.allow_spinning`, thread affinities |
| `MLSERVER_MODEL_ONNX_PROVIDER_OPTIONS` | JSON | e.g. `cudnn_conv_algo_search` |
| `MLSERVER_MODEL_ONNX_CUDA_GRAPH` | true/false | CUDA graph replay |

The Docker-engine suites (bench/suites.py) additionally sweep through
both env vars and `parameters.extra` in `model-settings.json`:

| Suite | Settings | Mechanism |
|---|---|---|
| `processing` | `rest_worker_json`, `rest_binary_tensor`, `rest_worker_binary`, `parallel_inference_transport` | `MLSERVER_*` env vars + binary tensor request encoding |
| `framework` | `session_options` (intra/inter-op threads, mem pattern, CPU arena, log severity), `providers`, `provider_options` (cudnn, arena), `run_options`, `session_config_entries`, `cuda_graph`, `cuda_blocking_sync` | `parameters.extra` (framework pydantic auto-resolve) |
| `middleware` | `gzip_enabled`, `access_log`, `metrics_endpoint`, `use_structured_logging`, `tracing_server` | `MLSERVER_*` env vars |
| `codec` | `parameters.content_type` (np/pd), sklearn `predict_fn` | `parameters.content_type` / `parameters.extra` |
| `grpc` | `grpc_raw_input_buffers`, `grpc_max_message_length` | `MLSERVER_*` env vars + raw vs typed gRPC contents |

Notes:
- `rest_worker_binary` requires `rest_binary_tensor`.
- ORT enum-typed options (`execution_mode`,
  `graph_optimization_level`) cannot be expressed in JSON settings —
  pybind rejects plain ints at `setattr` (verified; excluded from
  suites by design).
- cuDNN `DEFAULT` algorithm search changes outputs numerically
  (9.0e-05) and fails the parity gate by design. Use HEURISTIC.
- Fork features that postdate the published `odh-master` image are
  feature-probed at runtime; unsupported variants record
  `SKIPPED_UNSUPPORTED_IMAGE` instead of measuring an unapplied
  setting.

## Images

`infrastructure/images.json` pins the known digests (baseline, ship).
Variant generators read it; override every variant's image with:

```bash
make run-plan DOMAIN=... PLAN=... IMAGE=quay.io/you/mlserver@sha256:...
# or: BENCHMARK_IMAGE=... python3 tools/run.py ...
```

## Cluster targets

| Variable | Default | How to set |
|---|---|---|
| Namespace | `mlserver-perf` | `BENCHMARK_NAMESPACE`, `make ... NAMESPACE=` |
| oc context | current | `BENCHMARK_CONTEXT` |
| Client pod | auto-discovered (`app=mlserver-client`) | `BENCHMARK_CLIENT_POD` |
| GPU deployment | `mlserver-rfdetr` | `BENCHMARK_GPU_DEPLOYMENT` (hook) |
| CPU deployment | `mlserver-rfdetr-cpu` | `BENCHMARK_CPU_DEPLOYMENT` (hook) |

## Plan timing

Plans fix: 2 clients, 60 s warm-up, 60 s measured, 3 rounds,
≤20 ms start gate. Override for quick runs:

```bash
python3 tools/run.py --domain wire-format --plan stock-vs-binary \
    --rounds 1 --concurrency 8
```

Never publish results from reduced rounds — use them for smoke tests.

## Client pod resources

`infrastructure/manifests/client-deploy.yaml` reserves 4 CPU / 8 Gi for
the load generators on a node separate from the serving pods. The
serving deployments (GPU/CPU) request the full node — they never
coexist (the hook enforces this).
